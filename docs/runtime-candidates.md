# Runtime candidate comparison

Seven naturally linked Aztec Amiga 3.6a library object contributions match
226 bytes of resident CODE exactly, with no candidate relocations or overlapping
game relocations. Their identities are candidates: shared runtime code does not
uniquely select a compiler release. Game ownership totals and game-source proof
levels remain unchanged. The separate candidate-match total is regenerated by
the census and checked against the immutable executable.

| Library object | Resident offset | Code bytes |
| --- | --- | --- |
| index | 0x75d8 | 26 |
| movmem | 0x7a6c | 42 |
| strcat | 0x7a96 | 42 |
| strcmp | 0x7ac0 | 48 |
| strcpy | 0x7af0 | 16 |
| strlen | 0x8044 | 18 |
| strncpy | 0x7956 | 34 |

These are complete object contributions, not necessarily single functions.
For example the string comparison object includes more than one entry path.
No original game code is used to build any of the comparison artifacts.

The librarian extracts named members from the pinned c.lib. The historical
linker produces isolated HUNK executables. The narrowly interpreted AJ code-size
field is corroborated by linking all seven objects together: precisely the same
226 concatenated code bytes and two final zero padding bytes emerge. We do not
trim arbitrary trailing zeros or claim to have a general AJ object parser.
Each complete contribution is searched at even offsets in CODE hunks; matches
that intersect a relocation are rejected. Artifact hashes and step return codes
are checked before comparison. The final job has 14 successful steps.

Reproduce after acquiring the archives recorded in `toolchain/aztec36-acquisition.json`:

```powershell
python tools/inventory_aztec36.py
python tools/aztec_worker.py prepare aztec36-new experiments/aztec36-smoke --commands experiments/aztec36-smoke/commands.json --aztec36
.\tools\run_worker.ps1 -Job build/worker-jobs/aztec36-new
python tools/aztec_worker.py collect build/worker-jobs/aztec36-new
python tools/runtime_match.py build/worker-jobs/aztec36-new
python tools/census.py --write
python tools/census.py --check
```

The [archival catalog](https://amigamuseum.emu-france.info/Fichiers/ADF/Utilitaires-Applications/)
provided four candidate disks. SHA-256 pins are acquisition identities, not
publisher authentication. Disks 1, 2 and 4 validate; disk 3 fails checksum at
block 1374 and remains unextracted. Executed tool banners identify 3.6a dated
12-18-87. Both 3.6a and 5.0a compile/link/run the independent arithmetic probe;
3.6a defaults to word-sized int arguments, while 5.0a defaults to long-sized.

Failures remain recorded in `evidence/experiments/`: no-input usage probes return
10; `-e` is not a supported 5.0a linker option; some requested 3.6a members are
absent or need other runtime symbols. The 5.0a strlen/strcmp/memcpy code did not
match resident code in either c.lib or c16.lib. No-match results alone do not
exclude a compiler. The initial broader 3.6a experiment also produced unmatched
rindex, setmem and toupper code. The final repeatable experiment limits itself
to the seven corroborated contributions; earlier receipts preserve failures.

A subsequent [overlay experiment](overlay-linking.md) verifies natural overlay
linking and the complete 244-byte segload contribution, including two relocations.
Together the candidate matches cover 470 bytes. Exact compiler flags and the
complete investment module reconstruction remain open.
