## Follow-up: gate-only alias proof route

The proposed alias was not implemented because the exact final-link call-site proof route is absent. F5FB2's compiled receipt has no relocation records from its overlay code hunk (HUNK 3); its complete relocation table contains only seven HUNK0-to-HUNK1 records, one HUNK0-to-HUNK0 record, and one HUNK1-to-HUNK1 record. In particular, no HUNK1 relocation exists at `stub + 2` for any of the seven `.F*` call sites, so `function_compare` cannot use its existing A4-stub relocation fallback to bind those final D16 operands to linked `.F*` symbols.

The pinned linker symbol map does contain unique HUNK0 definitions for `.Ffix`, `.Fsub`, `.Fdiv`, `.Fflt`, `.Fmul`, and `amiga_ffp`, and the AJ object contains the `.F*` names. Those facts do not bind each final encoded call-site displacement to the corresponding symbol under the required linked relocation check. The original executable is pinned at SHA-256 `00ad5a2860110701d5fe2acd6834d0a9c819d6659a8af9bdbc1a9e1a99aea481`; original gates are byte-exact and unique as described in `experiments/worker-resident-object/gate-alias-design.md`. The missing link-side call-site identity proof is therefore a blocker; no alias or `FUNCTION_CODE_MATCH` claim was added. Preserve the existing isolated `DIFFER` verdicts.
